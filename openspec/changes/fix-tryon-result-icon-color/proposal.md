# Proposal：試穿結果空預覽播放圖示對齊設計稿

## 為什麼

GitHub PR review 留言（@nelsonliu-eslitec）指出 `TryOnView.vue` 結果區空預覽的播放圖示「好像是灰色的」，並附上 Figma 連結（node `841:618`，`ph_video`）要求檢查。

先用 Figma MCP 取得該節點的設計上下文與截圖，圖示被匯出為攤平的向量資產，色碼無法直接讀出，僅能從截圖初步判斷是偏藍灰、非純灰階，與現有 `color: $babyBlue`（`#a5c8e6`）視覺上相近，因此第一輪回覆判斷「未發現明確落差」。

使用者接著直接提供了 Figma 節點的原始 SVG 原始碼：

```svg
<path d="M32.0001 53.3337C43.7822 53.3337 53.3334 43.7824 53.3334 32.0003C53.3334 20.2183 43.7822 10.667 32.0001 10.667C20.218 10.667 10.6667 20.2183 10.6667 32.0003C10.6667 43.7824 20.218 53.3337 32.0001 53.3337Z" stroke="#AEB8CC" stroke-width="2"/>
<path d="M27.3333 22.667L41.3333 32.0003L27.3333 41.3337V22.667Z" fill="#AEB8CC"/>
```

比對後找到兩處實際落差：

- **顏色**：Figma 實際色碼是 `#AEB8CC`（RGB 174/184/204，偏灰的藍灰色），現有實作用的是 `$babyBlue`（`#a5c8e6`，RGB 165/200/230，飽和度較高、偏鮮豔的天藍色）。兩者雖然同色系，但 `$babyBlue` 明顯比設計稿更藍更亮，難怪在畫面上會被誤認為「不是設計稿要的顏色」
- **幾何比例**：Figma 的圓形半徑約為 21.33（viewBox 64 的 1/3），描邊 `stroke-width: 2`；現有實作圓形半徑是 30（幾乎撐滿整個 64×64 的圖示框），描邊 `stroke-width: 3`。現有圖示因此顯得比設計稿粗大很多，視覺重量、留白比例都對不上，這也是造成「看起來灰灰的、跟設計稿感覺不一樣」的另一個原因（圖示過大過粗，顏色的視覺份量被放大，更容易顯得灰暗）
- 三角形播放符號的座標也一併對齊成 Figma 原始座標（`27.3333,22.667 / 41.3333,32.0003 / 27.3333,41.3337`），取代原本手繪的近似座標

## 做了什麼

- `src/components/icons/IconPlayCircle.vue`：把 `<circle r="30" stroke-width="3">` ＋ 手繪三角形，改成 Figma 原始的圓形路徑（半徑 21.33、`stroke-width: 2`）與三角形路徑座標；保留 `stroke="currentColor"` / `fill="currentColor"`，維持與其他圖示元件一致、由外層 CSS 控制顏色的慣例
- `src/views/TryOnView.vue`：`.result__box` 的 `color` 從 `$babyBlue` 改成 `#aeb8cc`（Figma 實際色碼，目前色票變數裡沒有對應項目，比照專案裡 `#606692` 的既有慣例直接用原始色碼）
- `openspec/specs/tryon-ui/spec.md`：「首次進入與生成完成狀態分離」Requirement 補上圖示幾何／顏色的明確數值與新 Scenario、trace

## 影響範圍

`IconPlayCircle` 元件目前只有 `TryOnView.vue` 結果區的空預覽在用，改動只影響這一處的視覺呈現，不影響試穿生成的互動邏輯或其他頁面。
